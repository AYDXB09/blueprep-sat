Ad-hoc Practice Builder

/practice/new

Directly answers "give me a practice test of N questions in Math in these 2 sections" — N is never hardcoded, and shown here in its full "Both" state: Math and R&W get independent counts, each with its own +/− stepper (any value, no upper-bound nagging — a "22" is just as valid as a "21," the stepper doesn't second-guess it). Standard-length quick-picks (Quarter/Half/Module/Section) jump both counts to the nearest official size at once; the +/− steppers work free-form the rest of the time.

Timer sums each subject's own pace rather than blending — Math and R&W genuinely pace differently (95 vs. 71 sec/question), so "53 min combined" here is two real numbers added together, not one averaged guess.

The pool check banner fires before the set is built, not after — with ~3,250 questions in the bank this should be rare, but a narrow filter combination (a less-common domain + "new questions only" + high difficulty, say) can still come up short. Better to say so and offer a choice than silently serve fewer questions than asked for.

  • "Start N-question set"→ Practice Player (new session created)

Full Test Setup

/test/new

Not a filter builder like the Ad-hoc screen — a full test's module structure is fixed, matching the real exam format. What is new here: Module 2's difficulty tier isn't chosen by the student, it's routed automatically from Module 1 performance, creating rows in session_modules as each module completes.

Honest caveat, shown in-product too, not just here: the real tier-routing threshold isn't publicly documented by the source. BluePrep's cutoff (roughly, Module 1 accuracy above a calibrated threshold → Tier 1) is an approximation, not a reverse-engineered exact match — the existing app already says as much about its difficulty-mix calibrations, and this should say the same rather than imply more precision than it has.

  • "Begin full test"→ Practice Player (Module 1 only; Module 2 is chosen after)

Practice / Test Player

/practice/{session_id}/q/{n}

The Bluebook-style player, reused from the existing app — strike-through, highlighter, and a timer whose display follows this session's timer_mode (per-question / session-only / none). Every submit writes a question_attempts row immediately (not batched at the end), so an abandoned session still has partial data.

Pause is always available, regardless of timer_basis — sets practice_sessions.paused_at, resume folds the elapsed time into total_paused_seconds so it never counts against the student. When the clock hits zero, nothing auto-submits — the alert shown here offers a real choice; "keep going" starts accumulating overtime_seconds instead of silently ending the session.

A question with is_active = false always shows the "Retired" chip, whether or not this session includes retired questions — the chip is a fact about the question, not a setting. If feedback_mode = 'immediate', correctness shows right after submit; if 'end_of_session', nothing is revealed until Session Summary.

  • Finish last question→ Session Summary
  • Exit mid-session→ Dashboard (session stays open, resumable)

Question Layout — Small vs. Long

layout detail, not a distinct route

Same two-pane player, two real content shapes. A short stimulus (a one-sentence grammar fix, a short grid-in) fits entirely in the pane with no scrolling — nothing about the layout changes, it just doesn't fill the space. A long stimulus (a full R&W passage, a dense multi-part Math word problem with a table) scrolls independently inside its own pane — the stem and answer choices stay fixed and visible, matching how the real Bluebook interface keeps the question you're answering from moving while you reread the passage.

This matters for the trap/cue overlay work from earlier too: cue highlights inside a long, scrolled stimulus need to stay correctly positioned relative to text that isn't fully visible — worth testing against a genuinely long passage early, not just the short examples used in the mockup so far.

Mistake Log

/mistakes

Persistent across every session, not scoped to one — a question only leaves this list once answered correctly, matching the spaced-resurfacing idea from the earlier brainstorm. Query is a join of question_attempts filtered to the latest attempt per question being incorrect. "Retry all" spins up a new practice_sessions row with mode='retry_mistakes' and question_ids set to exactly this list.

  • "Retry all"→ Practice Player (new retry session)
  • Click a row→ Review card (trap/cue overlay)

Settings

/settings

Every control here writes straight to user_settings — one row per user, real typed columns rather than a jsonb bag, since every value here has a known, small set of valid options. These are defaults, not locks: the Ad-hoc Builder and Full Test Setup screens read from here to pre-fill, but changing a setting mid-account never rewrites an already-created practice_sessions row.

"Include retired questions" defaults to on — the earlier instinct to silently filter them was wrong. Retired questions are always visibly tagged wherever they appear (see Player screen), and this setting only controls whether they're offered in newly built sessions at all, not whether they're hidden once encountered.

  • Change any settingsaves immediately, no separate "Save" step
  • Sidebar "Account"→ Settings (entry point from anywhere)
